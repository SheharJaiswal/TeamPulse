

20. **Habit activity submission semantics — OPEN / BLOCKS ACTIVITY API AND UI:** Approve the cardinality of submissions (one per habit/activity date versus multiple countable submissions), whether accepted submissions are immutable or correctable/deletable, which activity dates are allowed (today only versus bounded backdating versus the habit's configured active date range), the calendar/time-zone interpretation of an activity date, and whether/how quantity contributes to daily/weekly targets. Recommended MVP: allow multiple append-only count submissions per habit/date, require a positive bounded integer quantity, use an employee-selected calendar date validated against the habit's configured date range, and enforce request idempotency with a client-generated key. Do not implement these recommendations until explicitly approved; streak and target-progress calculations remain out of scope until their rules are approved.
